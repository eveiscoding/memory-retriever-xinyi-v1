# Explicit time/versioning and complementary fact recall

Logic-only, model-free experimental building blocks. These are independent
implementations inspired by [Graphiti's fact timestamps](https://github.com/getzep/graphiti/blob/main/graphiti_core/edges.py)
and [Hindsight's complementary recall](https://hindsight.vectorize.io/0.9/developer/retrieval),
consulted 2026-10-22. No upstream code/package is imported. They do not replicate
Graphiti's automatic graph extraction or Hindsight's complete TEMPR system.

## Stage 1: explicit bitemporal versions

Enable `AML_FLAG_FACT_VERSIONS=1` only in an isolated test database. Existing cited
facts can be annotated through the **internal** Python API:

```python
first = db.record_fact_version(
    user_id="alice", fact_id=old_fact_id, operation_id="employment-v1",
    version_key="alice:employment", valid_at=1704067200000,
)
second = db.record_fact_version(
    user_id="alice", fact_id=new_fact_id, operation_id="employment-v2",
    version_key="alice:employment", valid_at=1711929600000,
    supersedes=first["version_id"],
)
snapshot = db.facts_as_of(
    user_id="alice", valid_at=1706745600000, known_at=knowledge_time_ms,
)
```

- World validity is `[valid_at, invalid_at)`, Unix milliseconds; `invalid_at=None`
  is open-ended. `valid_at=None` is unknown, NOT the message/ingestion date and
  NOT an always-valid fact. Unknown validity is excluded from temporal answers.
- System knowledge is `[recorded_at, retired_at)`, generated by the store clock.
  A later update never claims it was known earlier. Precision is milliseconds.
- Supersession retires the prior *system assertion*, keeps it for old knowledge
  snapshots, and appends a revised assertion that closes its world interval at
  the new fact's effective time. A future-effective update does not prematurely
  hide today's old fact. An earlier bounded end is never extended.
- Subject/relation `version_key` and predecessor are supplied explicitly, not
  inferred by lexical overlap. Keys and speaker roles must match; overlapping
  versions require an explicit active predecessor. New effective time must be
  strictly later. Arbitrary same-start corrections, full backfill reconciliation,
  automatic conflict detection and natural-language time inference are deferred.
- Operation IDs are user-scoped and idempotent; payload changes conflict.
  Validation and all version writes are one transaction. A backwards system clock
  fails closed. Raw evidence and extracted fact text are never overwritten.
- `facts_as_of` is bounded (default100/max1000); it is not an unbounded history
  export. Nothing is automatically versioned merely by switching this flag on.

## Stage 2: complementary routes and source projection

Master switch `AML_FLAG_COMPLEMENTARY_RECALL=1` is **off by default**. Within it,
independent masks `AML_FLAG_FACT_RECALL_KEYWORD/GRAPH/TEMPORAL/SEMANTIC` default
to1 and can each be disabled. No providers/models are configured or called by
default. The semantic arm uses an explicitly supplied existing embedding backend,
otherwise reports `unavailable`; it never masquerades as keyword semantics.

```python
db.link_fact_entity(user_id="alice", fact_id=fid, entity="Orion",
                    message_id=source_id, quote="Alice joins Orion.")
audit = db.recall_facts(user_id="alice", query="Alice", limit=50)
```

Entity links require a label in an exact quote anchored to this fact's original
citation. They are manually curated in this stage; no NER, aliases or inferred
causal relationships. Latin labels use word boundaries; Chinese labels use
literal substring matching. Two-hop traversal is explicitly bounded and can find
another fact through a shared entity even without direct query-word overlap.
Entity links carry their own recorded-at time and obey knowledge cutoffs.

| Route | Implementation | Model-free validation |
| --- | --- | --- |
| Keyword | Separate fact FTS5 BM25, independent of raw-message FTS | Distinct keyword-only fixture |
| Graph | Cited entity→fact→entity expansion, max2 hops | Second-hop complementary result and hop/tenant bounds |
| Temporal | Explicit point-in-time version eligibility | Historical/future/unknown and half-open boundaries |
| Semantic | Optional backend cosine similarity | Stub vectors, shape/nonfinite/error/budget rejection; NOT quality evidence |

Each arm produces a ranked list. Facts fuse equally with `sum(1/(60+rank))`,
stable fact-ID ties, one contribution per fact/arm. This implementation executes
SQLite routes sequentially on one connection; it does not claim Hindsight's
parallel performance, inference quality or complete graph architecture.

`recall_facts` returns derived text, source references, channel ranks/statuses,
candidate truncation, eligible count and time cutoffs. A missing/failing semantic
backend cannot remove keyword/graph/temporal results. Errors persist no provider
exception text. Only facts from the selected user reach an embedding backend.

Date interpretation is deliberately narrow: one explicit ISO `YYYY-MM-DD` means
UTC midnight **point validity**, not a whole-day range. Alternatively pass
`valid_at` milliseconds directly. Multiple/invalid dates reject the fact recall;
"yesterday", year-only and vague phrases are not guessed. Explicit temporal or
knowledge filters require `fact_versions`. Unversioned/unknown facts are excluded
from dated retrieval. With no date, versioned facts use current world validity;
unversioned facts remain available. Supplied `known_at` excludes future facts,
annotations and source messages, but BM25 is not a historical index replay.

### Ordinary Search compatibility

With the master off, raw Search behavior is unchanged. With it on, selected facts
are **projected back to original message IDs** before entering the existing
candidate union: Search still returns original messages, never a paraphrased
fact posing as evidence. Existing dedup, slots and optional pair reranking apply.
The fused source list joins raw RRF once at experimental weight0.1; individual
fact-arm ranks are diagnostics only, avoiding four separate boosts. This is a
hierarchical integration, not the same scoring recipe as Hindsight.

`recall_status` is emitted only when Search provenance is enabled. Failure of the
optional sidecar falls back to raw recall and reports failure on returned
evidence. There is no new HTTP route or request field. These sidecar temporal
constraints do NOT globally filter raw Search results: historical raw evidence
remains searchable. Use `facts_as_of`/`recall_facts` for explicit temporal filters.
No claim of a precision, recall or ranking gain is made before real effect tests.

## Budgets and lifecycle

| Environment setting | Default | Range |
| --- | ---: | --- |
| `AML_FACT_RECALL_SCAN_LIMIT` | 1000 | 1–10000 facts/user |
| `AML_FACT_RECALL_CHANNEL_LIMIT` | 50 | 1–400 per arm |
| `AML_FACT_RECALL_GRAPH_HOPS` | 2 | 1–2 |
| `AML_FACT_RECALL_EMBED_CHARS` | 64000 | 1–1000000 characters total |
| `AML_FACT_RECALL_RRF_K` | 60 | 1–10000 |
| `AML_FACT_RECALL_WEIGHT` | 0.1 | 0–1 (ordinary Search fused source arm) |

Scan truncation is explicit; the bounded universe is stable fact-ID order, not
an exhaustive or globally optimal search. Source projection also has a candidate
budget. Each fact has at most16 curated entity citations.
Candidate budgets do not guarantee constant database query time as version
history grows; a user/fact/time index supports snapshot lookups.
Semantic inference is query-time and uncached in this prototype; a future network backend must enforce
its own timeout, cost and transport-size limits. No token-budget selector,
learned graph, mental-model/reflection stage or causal inference is implemented.

New derived tables/FTS are created during schema initialization; existing fact FTS
is backfilled only on explicit recall enable, with bounded batches and no model
calls. Raw FTS is never rebuilt by this feature. User deletion, TTL cleanup and
purge remove versions, operation records, fact FTS, links and citation tables.

## Item-by-item functional acceptance

Run only these related suites locally; full-suite validation belongs on server:

```bash
python -m unittest tests.test_facts -v
python -m unittest tests.test_temporal_facts -v
python -m unittest tests.test_complementary_recall -v
```

Add original privacy, concurrency, pair-rerank and API compatibility regressions
on server. Test success establishes functional wiring only. Model extraction,
entity/subject/relation resolution, real semantic recall quality, cost, latency
and end-to-end effect remain unverified until separately enabled and evaluated.
